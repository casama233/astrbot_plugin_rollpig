# ⭐ EX 成長：同一隻豬，養熟了會變樣

<div class="pig-highlight" markdown>

第一次抽到：**你好，新豬。**  
第二次抽到：**你怎麼又來了。**  
第五次、第六次還在來：**行吧，這已經是你家豬了。**

EX 系統就是把「重複抽取」從純粹的重複，變成一條可見的收藏成長線。

</div>

## EX Lv. 怎麼算？

```text
EX Lv. = max(0, 這隻豬的累計抽取次數 - 1)
```

| 你抽到這隻豬第幾次 | 顯示 |
| --- | --- |
| 第 1 次 | EX Lv.0（首次解鎖） |
| 第 2 次 | EX Lv.1 |
| 第 3 次 | EX Lv.2 |
| 第 4 次 | EX Lv.3 |
| 第 5 次 | EX Lv.4 |
| 第 6 次 | EX Lv.5 |
| 第 7 次以後 | EX 還會繼續升，但視覺差分最高沿用 Lv.5 |

## 現在是不是每隻豬都有「手寫」EX 文案？

**是。現在正式官方 catalog 的 201 隻豬，全部都有人工逐隻寫的 EX1～EX5。**

不是「10 隻精品 + 191 隻模板生成」了。現在是：

```text
99 隻 bundled 主目錄
+ 102 隻 compatibility 恢復舊豬
= 201 隻正式官方豬
= 201 隻全部精品手寫五級 EX
```

每一隻都有：

- 5 句各不相同的短描述；
- 5 段各不相同的完整文案；
- 沿原本角色梗／性格延伸的連續成長弧。

也就是說，你抽同一隻豬到 EX1、EX2、EX3、EX4、EX5，不是只看到「更熟了」「熟客版」「完全體」之類統一模板；每隻角色都有自己的故事方向。

例如有的豬從只會搞事慢慢學會掌握分寸，有的從被動困境慢慢長出主動選擇，有的則把原本純搞笑設定一路養成更完整的招牌梗。

## 這件事怎麼防止以後又退回模板？

現在 CI 不只檢查「最後有沒有 EX」，而是先檢查**人工 authoring 集合**：

```text
handcrafted EX IDs == official pig IDs == 201
```

而且每個 ID 都必須：

- 恰好有 EX1～EX5；
- 五級 `description` 全部非空且互不相同；
- 五級 `analysis` 全部非空且互不相同。

所以未來新增一隻正式官方豬，如果只靠安全生成器兜底而沒有補精品手寫文案，Resource Source gate 會直接紅，不能把它當成完成內容發布。

## 那個自動五級生成器還在嗎？

還在，但身份已經降成**安全兜底**。

它只負責：

- 本地自建／非官方小豬；
- 測試 fixture；
- 尚未納入正式 curated catalog 的臨時內容；
- 壞資料回退時避免整個 EX 展示斷掉。

正常官方 201 隻不應依賴它。正式 release 的內容 gate 會要求 201/201 明確手寫。

## EX 還能手工特製圖片或局部內容嗎？

可以。資源作者仍可針對 **EX Lv.1–5** 覆寫：

- 🖼️ 圖片
- 📝 短描述
- 💬 完整文案

第三方／本地作者不需要像官方內容庫一樣強制寫滿五級。稀疏差分仍按欄位向高級繼承：哪一級真的值得換圖或特製內容，就只寫那一級。

官方 201 隻「全手寫五級」是官方內容品質要求，不會破壞原本彈性的 EX 協議。

## EX 不會偷偷改什麼？

EX 是 **展示與收藏成長層**，不是偷偷把同一隻豬換成另一隻規則實體。

它不會修改：

- 小豬 ID
- 小豬名稱
- 抽取概率
- 保底規則
- 能不能烤、能不能吃之類的玩法資格
- 你的收藏權威資料

> 所以 EX Lv.5 不會突然因為「長大了」就把 10% 反噬改成 100%。雖然那聽起來很有節目效果。

## 哪些地方會看到 EX？

對玩家**已經真正擁有**的小豬，EX 差分可以出現在今日、歷史、週視圖、永久圖鑑以及相關料理卡等展示中。

但 `<span class="pig-command">/明日小豬</span>` 只是預測，不代表你已經擁有明天那隻，所以不會提前套用你的 EX 收藏差分。

## EX 和保底是什麼關係？

它們不是同一套東西：

- **EX**：告訴你「同一隻已經抽到第幾次」，並把重複變成可見成長。
- **新豬保底 / 跨日疲勞**：在重複太多時，增加下一次重抽到未解鎖小豬的機會。

一個負責讓重複抽取**有成長感**，另一個負責避免你**永遠只見同一張豬臉**。

## 給管理員：可以不手改 JSON 嗎？

可以。插件提供獨立的 **EX 成長管理** 頁：

- 搜尋並選擇小豬；
- 編輯 EX Lv.1–5 的描述、完整文案；
- 上傳／移除每級差分圖片；
- 留空按本地稀疏規則繼承；
- 直接查看「實際生效預覽」。

管理員若只改了基礎小豬而沒有建立本地 EX，公共 EX 不會偷偷覆蓋本地修改；只有明確建立本地 EX 後，才會由本地 EX 取得最高展示優先級。

## 給創作者：我能把 EX 投稿公共源嗎？

可以。EX-aware 投稿會把基礎小豬資料／圖片、本地 EX 差分，以及被 EX 差分引用的圖片作為**同一次人工審核**提交。

審核員可以先看每一級差分與圖片；批准後 base + EX 在同一個 candidate resource 中完整驗證，再一起原子發布。通用 builder 仍能為未完成 EX 的非官方候選提供安全兜底，但如果一隻新豬要正式成為官方 curated catalog 的一員，就必須補齊五級精品手寫文案才能通過官方 release gate。

舊的、不含 EX 的投稿仍然相容；正式資源協議仍是 Resource Protocol v1。
