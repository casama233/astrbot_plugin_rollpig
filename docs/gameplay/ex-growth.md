# ⭐ EX 成長：同一隻豬，養熟了會變樣

<div class="pig-highlight" markdown>

第一次抽到：**你好，新豬。**  
第二次抽到：**你怎麼又來了。**  
第五次、第六次還在來：**行吧，這已經是你家豬了。**

EX 系統就是把「重複抽取」從純粹的重複，變成一條可見的收藏成長線。

</div>

## EX Lv. 怎麼算？

```text
EX Lv. = max(0, 這隻豬的累計抽取次數 - 1)
```

| 你抽到這隻豬第幾次 | 顯示 |
| --- | --- |
| 第 1 次 | EX Lv.0（首次解鎖） |
| 第 2 次 | EX Lv.1 |
| 第 3 次 | EX Lv.2 |
| 第 4 次 | EX Lv.3 |
| 第 5 次 | EX Lv.4 |
| 第 6 次 | EX Lv.5 |
| 第 7 次以後 | EX 還會繼續升，但視覺差分最高沿用 Lv.5 |

## 現在是不是每隻豬都有 EX 文案？

**是。正式 active catalog 裡的每一隻豬都會有 EX1～EX5 五個不同的文字階段。**

這不只包含插件 bundled 的新豬，也包含從兼容下限恢復進正式公共源的舊豬。每級至少都有：

- 一句不同的短描述；
- 一段不同的完整文案。

其中一批代表性小豬另外有人手逐級精修的專屬 EX 文案；其他豬先以自己的原始角色描述／分析為核心生成穩定、可重現的五級成長基線。以後可以繼續把更多豬升級成完全手寫版本，而不會出現「沒寫就只有 EX 數字」的空洞狀態。

官方 Resource Source 在發布時也會把五級內容**直接寫進發布版 `pig_ex_variants.json`**。CI 要求發布後：

```text
EX 覆蓋小豬數 == 正式小豬總數
```

而且每一隻都必須真的具有 EX1、EX2、EX3、EX4、EX5 五級不同文案。

## EX 還能手工特製什麼？

資源作者可以針對 **EX Lv.1–5** 覆寫：

- 🖼️ 圖片
- 📝 短描述
- 💬 完整文案

作者依然不需要把五級完整複製一次。哪一級真的值得特製，就只寫那一級、那一個欄位；手工差分會疊在官方五級基線之上，並按欄位向高級繼承。

例如某隻睡覺豬只在 EX2 換圖和短描述、EX4 換完整文案、EX5 再換圖：沒有手工覆寫的部分仍然有該級官方成長文案，不會空白。

!!! success "完整基線 + 稀疏特製"
    **基線保證每級都有成長；稀疏差分負責真正值得特製的內容。**

## EX 不會偷偷改什麼？

EX 是 **展示與收藏成長層**，不是偷偷把同一隻豬換成另一隻規則實體。

它不會修改：

- 小豬 ID
- 小豬名稱
- 抽取概率
- 保底規則
- 能不能烤、能不能吃之類的玩法資格
- 你的收藏權威資料

> 所以 EX Lv.5 不會突然因為「長大了」就把 10% 反噬改成 100%。雖然那聽起來很有節目效果。

## 哪些地方會看到 EX？

對玩家**已經真正擁有**的小豬，EX 差分可以出現在今日、歷史、週視圖、永久圖鑑以及相關料理卡等展示中。

但 `<span class="pig-command">/明日小豬</span>` 只是預測，不代表你已經擁有明天那隻，所以不會提前套用你的 EX 收藏差分。

## EX 和保底是什麼關係？

它們不是同一套東西：

- **EX**：告訴你「同一隻已經抽到第幾次」，並把重複變成可見成長。
- **新豬保底 / 跨日疲勞**：在重複太多時，增加下一次重抽到未解鎖小豬的機會。

一個負責讓重複抽取**有成長感**，另一個負責避免你**永遠只見同一張豬臉**。

## 給管理員：可以不手改 JSON 嗎？

可以。插件提供獨立的 **EX 成長管理** 頁：

- 搜尋並選擇小豬；
- 編輯 EX Lv.1–5 的描述、完整文案；
- 上傳／移除每級差分圖片；
- 留空按本地稀疏規則繼承；
- 直接查看「實際生效預覽」。

管理員若只改了基礎小豬而沒有建立本地 EX，公共 EX 不會偷偷覆蓋本地修改；只有明確建立本地 EX 後，才會由本地 EX 取得最高展示優先級。

## 給創作者：我能把 EX 投稿公共源嗎？

可以。EX-aware 投稿會把基礎小豬資料／圖片、本地 EX 差分，以及被 EX 差分引用的圖片作為**同一次人工審核**提交。

審核員可以先看每一級差分與圖片；批准後 base + EX 在同一個 candidate resource 中完整驗證，再一起原子發布。即使作者只投稿基礎豬、沒有手工 EX，發布 builder 也會為它補齊五級官方文字基線。拒絕則不改動正式公共源。

舊的、不含 EX 的投稿仍然相容；正式資源協議仍是 Resource Protocol v1。
