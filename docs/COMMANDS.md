# 🐷 豬圈操作手冊：想搞什麼名堂，這裡都有趁手傢伙

本頁記錄的是**當前主線版本的實際可用指令**。死板的版本號往往比小豬老得還快，因此我們不再標註「以 v3.x.x 為準」；一切實際效果請以 `main.py` 內的 `@filter.command(...)`、後台功能開關，以及運行時即時生成的 `/豬豬幫助` 為準。

> `/豬豬幫助` 是每位養豬戶的第一站：它會根據群內實際開啟的玩法與數值動態生成，絕不會把已被管理員關閉的功能硬塞進面板裡。

> **QQ 原生 @ 操作提示：** 幫助卡片會在所有需要指定 `@` 目標的指令下方以高對比色特別標出。使用時請先手動敲出指令，再從 QQ 彈出的 `@` 選單中點選群友；切勿直接複製別人的整串指令、照搬畫面上的 `@某人`，也別單純手打對方暱稱，否則訊息將無法夾帶有效的原生 At 數據。

## 👤 群聊專屬署名機制

在群聊中觸發任何 RollPig 指令時，機器人發出的**首條回覆**都會在最頂端獨立佔用一行顯示 `@指令發起者`，方便大家在多人同時刷屏操作時，一眼認出這份結果究竟歸誰所有。

- 發起者的署名 `@` 會與下方的指令結果分行排版，絕不會和正文或圖片說明擠成一團。
- 像 `/烤群友`、`/吃群友` 這類需要額外指定 `@目標` 的互動玩法，被點名對象的提及依然會保留在後續的正式回覆內容裡，不會被頂端的發起者署名吞掉或取代。
- 如果原本的回覆內容一開頭就已經帶有同一位發起者的 `@`，系統會自動去重，不會重複標記兩次。
- 在私聊視窗中操作時，系統不會額外加上 `@` 署名。

無論是頂端的發起者署名、常規目標點名，還是隨機開烤群友，全都會統一走 `message_delivery.py` 的發送規範。其中 Discord、OneBot QQ、WhatsApp 以及現行的 QQ 官方適配器會採用標準 At 提及；Slack 採用原生文字點名；Telegram 則會透過已知使用者名稱或數字 ID 超連結進行標記。所有內部收藏 ID 在發送前都會先還原為各平台的原生 ID。

同一個 Discord 點名即便一處為原生 At、另一處為 `<@ID>`，最終也只會保留一次。Telegram 則會將點名與正文合併為同一段文字發出，避免被拆成兩條零碎訊息。若遇到發送回執逾時，系統不會重複補發點名；後續分段訊息也不會再次加上發起者署名。

## 🐣 今日抽豬

### `/今日小豬`

別稱指令：`/今日小猪`、`/今天是什麼小豬`、`/今天是什么小猪`、`/抽小豬`、`/抽小猪`、`/我的小豬`、`/我的小猪`、`/rollpig`。

- 每位玩家在同一自然日首次抽豬後結果即鎖定；重複查詢只會重看，不會重抽。
- 正常抽豬會同步更新永久豬籍、返場次數、EX 等級與各項累計統計。
- 換日分界線由 `timezone` 決定。
- 就算昨天不幸被吃掉，今天依然能正常開抽；今日首抽可能會依 `eaten_next_day_failure_percent` 機制強制從已解鎖圖鑑裡撈出一隻重複豬，不會卡死或鎖天。

### `/今日小豬 @某人`

需帶入 `at_view_pig=true`。此為**純旁觀偷看**：若對方已抽就亮出既有結果，未抽則僅提示尚未開抽，絕不代抽、不代解鎖，也不會引爆對方的預約烤豬結算。

## 📚 豬籍檔案、歷史紀錄與翻牌

### `/我的豬圈 [頁碼]`

別稱指令：`/我的猪圈`、`/小豬圖鑑`、`/小猪图鉴`、`/豬圈`、`/猪圈`。

- 每頁 12 隻。
- 檢視當前有效圖鑑的解鎖進度，以及玩家名下仍持有的歷史保留小豬。
- 每隻豬都會標註累計入手次數與 EX Lv.。
- 範例：`/我的豬圈 2`。

### `/昨日小豬`

別稱指令：`/昨日小猪`、`/昨天小豬`、`/昨天小猪`。調閱昨天實際存檔的抽豬結果；若無紀錄便會直白告知沒有。

### `/明日小豬`

別稱指令：`/明日小猪`、`/明天小豬`、`/明天小猪`。

推算明日固定預測與 1–5 星「明日豬運」，但**不會提前寫入明日結果，也不會提前解鎖豬籍**。

### `/本週小豬`

別稱指令：`/本周小猪`、`/本周小豬`、`/本週小猪`、`/本週小豬`、`/本周猪报`、`/本週豬報`。

彙整當前曆週週一至週日的動態總覽；未抽與尚未到來的日期各有對應標示，被吃等已儲存狀態亦會如實保留。

### `/隨機小豬 [1-9]`

別稱指令：`/随机小猪`、`/随机小豬`、`/隨機小猪`、`/随机猪`、`/隨機豬`。

預設抽取 1 隻，也可自訂 1–9。純粹從現行有效圖鑑中隨機翻牌展示，**不影響今日結果，亦不記入永久解鎖**。

### `/找豬 關鍵詞`

別稱指令：`/找猪`、`/搜豬`、`/搜猪`。

檢索 `id / name / description / analysis`，結果卡片最多列出前 9 隻並附上總符合筆數。

## 🍳 `/今日烤豬`

別稱指令：`/今日烤猪`、`/烤豬`、`/烤猪`。需搭配 `enable_roast=true`。

- 前提是自己今天已經抽到小豬。
- 不會更動今日抽豬結果，單純產出一張料理圖卡。
- 人類、已被吃掉或不可烹調的形態會直接被擋下。
- 當 `enable_ai_roast_copy=true` 時，可呼叫當前對話模型撰寫專屬料理文案；若遇服務不可用、逾時或失敗，則自動降級使用本地預設模板。
- 同一隻豬在同一天內最多只會實際發起一次模型生成請求；成功產出的文案在近七日內可重複沿用。

### 投餵料理卡

開啟 `enable_roast_feeding` 後，先在群裡用 `/今日烤豬` 出一張自己的料理卡。每人每天在同一群可送一份，每人每天在同一群可收一份。

| 指令 | 效果 |
| --- | --- |
| `/今日烤豬 投餵 @群友` | 當場投餵，雙方今天須已在本群抽過豬。 |
| `/今日烤豬 明天投餵 @群友` | 留到對方明天在本群抽豬時生效。對方最近七天內須在本群抽過豬。 |

突變限當天、當群，會顯示在今日小豬卡上。下列機率以群烤的基礎機率為準。若同時帶有週一祭品光環，最多把 10 個百分點從逃脫移到成功。所有臨時 EX 調整最低到 EX0，永久圖鑑的 EX 仍依抽中次數計算。

| 詞條 | 效果 |
| --- | --- |
| 帶刺爆辣 | 反噬率 10% → 20%。 |
| 爆汁增幅 | 被成功烤到時，料理卡臨時 EX +1。 |
| 致幻 | 每份菜固定判定一次。兩種結果各占一半：今日卡 EX +2，或今日卡 EX −2、逃脫率增加 15 個百分點。留到隔天吃的菜會在對方於本群抽豬時顯示結果。 |
| 情緒穩定 | 成功率 100%，出鍋料理卡臨時 EX −1。 |
| 嚼不動 | 預約烤變成 40% 成功、50% 逃脫、10% 反噬。隨機烤成功時，料理卡臨時 EX +1。 |
| 黃油滑蛋 | 50% 成功、50% 逃脫、0% 反噬。出鍋料理卡臨時 EX +2。 |
| 紅溫警告 | 65% 成功、0% 逃脫、35% 反噬。今日卡和出鍋料理卡各有臨時 EX +1。 |

## 🔥 `/烤群友 @某人`

限定群聊使用，且需提供 `enable_roast=true` 與 `enable_group_roast=true`。無法對自己開火；想把自己做成菜請改用 `/今日烤豬`。

當目標已有可料理的今日小豬時，一般開烤會扣除 **1 格 Roast Charge**，再按下列基礎機率結算。投餵突變和週一光環可調整機率。

- **70% 成功**：目標順利上桌，實際苦主記上一筆被烤紀錄；
- **20% 逃脫**：無人被成功烤熟；已消耗的 Charge 概不退還；
- **10% 反噬**：若主廚自身處於可料理狀態，實際苦主當場反轉為主廚本人。

### Roast Charge 並非舊版的「整段式冷卻」

每位玩家在各個群組中獨立擁有 Charge 槽位，預設上限為 `2 / 2`。`group_roast_cooldown_hours` 代表**每缺一格 Charge 的自然回充時間**，預設 8 小時；並非「開烤一次就整個人鎖死 8 小時」。

未發佈維護版的幫助卡會依此實例的容量與恢復時間顯示，保留小數小時；同時標明普通點火消耗 1 格、逃脫不退款、吃群友成功率與失敗吃掉自己的代價。收藏 EX 等級可超過 5，幫助中的文案差分說明不表示收藏等級上限；高等級沿用最高可用差分。

唯有設定為 `group_roast_max_charges=1` 時，體感才接近舊版的單格冷卻節奏。

## 🪤 目標尚未抽豬：預約埋伏烤豬

需要 `enable_roast_reservation=true`。

首位符合資格的玩家執行 `/烤群友 @尚未抽豬目標`：

- 鎖定成為本單固定主廚；
- 自身必須持有可料理狀態的今日小豬；
- 建立本群當日預約單並當場預付 **1 格 Charge**；
- 建單當下即自動計為第 1 位參與者。

後續跟單加入：

- **首選推薦**：`/添柴 @目標`；
- **相容寫法**：再次輸入 `/烤群友 @同一目標`；
- 跟單添柴無需再扣自身 Charge；同一位玩家不會重複計算人數；
- 單筆預約預設上限 12 人（含主廚本人）；
- 目前添柴人數多寡不會額外拉高 70/20/10 的成功率。

待目標本人在**同一群組**亮出自己的今日小豬時，懸掛的預約單便會一次性自動引爆結算；純粹旁觀的 `/今日小豬 @某人` 不會觸發。結算當下也不會重複扣除主廚第二格 Charge。

詳見 [ROAST-RESERVATIONS.md](ROAST-RESERVATIONS.md)。

## 🪵 `/添柴 [@目標]`：單一指令，雙重後廚情境路由

別稱指令：`/加柴`。

這是目前官方標準的添柴入口：

1. **場上有進行中的補貨輪次 + 單發 `/添柴`** → 自動支援烤箱補貨。
2. **`/添柴 @目標`** → 明確指名加入該目標的待結算預約單。
3. **無補貨進行中 + 場上僅有一張待結算預約 + 單發 `/添柴`** → 自動併入該張預約單。
4. **無補貨進行中 + 場上有多張待結算預約 + 單發 `/添柴`** → 系統會要求明確指定 `@目標`。
5. 主廚若試圖替自己的預約重複添柴 → 系統會直接提醒建單時已計為 1 人，不會異動參與名單。
6. 凡屬重複加入、食材本人誤闖、名額已滿或查無有效預約等情況，皆由外掛程式直接攔截駁回，不會交給 LLM 自由發揮。

### 舊版補貨指令相容區

`/添煤`、`/加煤`、`/烤箱添煤`、`/烤箱添柴` **僅保留作為補貨相容入口**。它們不會接入上下文預約路由，也不會出現在動態幫助的主推清單中。

## ⛽ `/烤箱補貨`

別稱指令：`/烤箱补货`、`/烤箱补给`、`/烤箱補給`。需同時啟用群烤與 `enable_oven_refill=true`。

- 僅限群聊環境內運作。
- 發起人與所有響應支持者，均須為當天已在本群留下 RollPig 活躍足跡的成員。
- 發起人建單時自動計為首位支持者。
- 達成門檻在發起當下即依當時群內活躍人數與當日已成功補貨輪數鎖定。
- 同一輪補貨中，每位玩家僅採計一次支持。
- 直接輸入 `/添柴` 即可支持當前的補貨輪次。
- 人數達標後，系統會為本群符合資格且**目前確實缺少 Charge** 的活躍玩家，每人最多恢復 1 格體力，不會直接補滿，也不會超過上限。
- 每輪補貨都有有效時限（TTL）；如果超時仍未湊齊人數，就必須重新發起。
- 結算一旦開始，若發生儲存錯誤或意外中斷，系統將採取 fail-closed 封帳機制，防止重試導致重複發放獎勵。

詳見 [ROAST-CHARGES.md](ROAST-CHARGES.md)。

## 🎲 `/隨機烤群友`

別名：`/随机烤群友`。系統會從今天本群內實際擁有「可料理小豬」的其他成員中隨機挑選目標，再進入一般群烤流程；不會替尚未抽豬的人建立隨機預約。

## 🛡️ 次日被烤保護

判斷是否觸發 `enable_roast_protection=true` 時，系統會依據**同一群組**昨天實際被烤到的次數來計算：

- 成功烤到目標（victim）：計入次數；
- 目標成功逃脫：不計入次數；
- 料理失敗遭到反噬：計入真正被反噬的主廚頭上；
- 僅建立預約但尚未結算：不計入次數。

達成 `roast_protection_threshold` 條件後，今天的一般烤群友、建立預約以及普通吃群友隨機選目標，都會尊重此保護機制。雖然後門指令可無視保護，但依然無法繞過「沒抽豬／變成人類／已被吃掉／不可料理」等基本限制。

## 🍴 `/吃群友 @某人`

此功能需開啟 `enable_group_eat=true` 並僅限在群聊中使用。

- 成功率由 `eat_success_percent` 參數決定，預設值為 15%。
- 成功時：目標今天的狀態將變為「吃掉了」。
- 失敗時：發起者自己反而會變成「吃掉了」。
- 被吃掉的玩家隔天依然可以正常抽豬；不過當天的首次抽取會依照 `eaten_next_day_failure_percent` 的設定，判定是否強制抽出一隻已解鎖的重複小豬。
- 人類既不能吃人也不能被吃；狀態為「吃掉了」的玩家無法再次被吃；一般模式挑選目標時會遵守次日保護規則。

### `/隨機吃群友`

別名：`/随机吃群友`。系統會從今天本群內可被吃且未受保護的其他成員中隨機挑出一位，接著執行一般的吃群友流程。

## 📰 `/豬圈日報`

別名：`/猪圈日报`、`/今日豬圈日報`、`/今日猪圈日报`。

手動觸發並生成本群今日的統計海報，內容涵蓋活躍度、抽豬、成功燒烤、被吃、逃脫、反噬、熱門豬種及並列稱號。**手動查看僅供讀取數據，不會觸發可選祭品機制。**

管理控制入口：

- 查詢狀態：標準指令為 `/猪圈日报状态`；同時支援 `/豬圈日報狀態` 及帶空格的 `/豬圈日報 狀態`。
- 開啟功能：標準指令為 `/猪圈日报开启`；同時支援 `/豬圈日報開啟` 及帶空格的 `/豬圈日報 開啟`。
- 關閉功能：標準指令為 `/猪圈日报关闭`；同時支援 `/豬圈日報關閉` 及帶空格的 `/豬圈日報 關閉`。

無論是簡體標準指令、繁體或混合字形的別名，還是舊有的帶空格寫法，都會統一交由 Daily Report 處理器執行。目前各群的自動推送預設為關閉，相關管理操作需具備 AstrBot 管理員權限。

### 週日小報與週一祭品

開啟 `enable_weekly_tabloid` 後，已訂閱自動日報的群會在週日最晚 22:00 排程發八卦小報。小報統計週一到發刊時的本群玩法，並接替當日的自動日報及其選配獻祭。`/豬圈日報 八卦` 可在群裡查看週資料及已發出的當期小報。

本週在本群抽過豬的人可在小報發出後用 `/豬圈日報 投票 1` 投票，把 `1` 換成候選人編號。有按鈕的 Discord 可直接點選。每人一票，在插件時區的週日午夜截止。最多五名候選人依抽豬天數排列，同分按固定順序，票數相同時依候選順序決定。至少兩名候選人才開票，零票的群週一照常。

圖片週刊會附上文字投票指令、候選編號與截止時間。圖片產生失敗時，群裡會收到完整的文字週刊。

週一得票者在該群看到的今日小豬卡附有祭品光環與 1 級臨時 EX。普通烤群友時，他的逃脫率會下降 10 個百分點，這部分加到成功率。原有的烤豬保護照常生效。

以下指令皆通往同一個強制執行流程：`/打點後廚`、`/打点后厨`、`/偷換烤架`、`/偷换烤架`、`/賄賂主廚`、`/贿赂主厨`、`/加急生火`、`/強行點火`、`/强行点火`。

- 使用時必須明確指定目標對象。
- 一般後門指令每位發起者每天限用一次。
- 可直接無視普通的 Charge 消耗、次日保護以及 70/20/10 限制，直接進入成功結算。
- **但依然無法繞過基本資格限制**。
- `/強行點火` 僅限 AstrBot 超級管理員使用。

## 常見誤解

### 輸入 `/添柴` 會不會有時候送錯鍋？

系統不會靠猜測執行。當有補貨正在進行時，單獨輸入 `/添柴` 會優先支援補貨；若要加入特定預約，請明確輸入 `/添柴 @目標`；只有在場上僅有一張預約且沒有補貨活動時，系統才會自動幫你添柴到那一張。

### `/添煤` 這個指令被移除了嗎？

並沒有。它依然作為補貨的相容入口保留著，只是不再擔任玩家的主要指令，也不會參與預約系統的路由分配。

### 在指令裡 @ 別人，會不小心幫對方抽豬嗎？

不會。`at_view_pig` 屬於純讀取操作，不會替他人進行抽取。

### 使用 `/隨機小豬` 會直接幫我解鎖圖鑑裡的豬籍嗎？

不會。這個指令僅提供資料展示，不會影響解鎖進度。

### 執行 `/明日小豬` 會提前鎖定明天真正的抽豬結果嗎？

不會。它雖然提供固定的預測結果，但既不會提前寫入資料庫，也不會預先解鎖圖鑑。

### 被群友吃掉之後，今天是不是就徹底不能玩了？

「吃掉了」的狀態只會持續到當天結束；隔天你依然可以正常抽豬，只是當天的第一次抽取可能會依照設定機率，強制抽出一隻你已經解鎖過的重複小豬，絕對不會把狀態延續鎖到隔天。
