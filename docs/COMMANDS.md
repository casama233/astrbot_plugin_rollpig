# 聊天指令與玩法規則

本文以 v3.3.0 的 `main.py` 實作為準。簡體、繁體別名在多數常用指令上都已提供；實際是否需要 `/` 前綴由 AstrBot 當前指令配置與適配器決定。

## 快速幫助

### `/豬豬幫助`

常用別名：

- `/猪猪帮助`
- `/小豬幫助`
- `/小猪帮助`
- `/rollpig幫助`
- `/rollpig帮助`

生成一張完整指令幫助卡。當功能開關或數值配置改變時，幫助卡會使用目前運行時設定顯示部分資訊。

## 每日抽取

### `/今日小豬`

常用別名：

- `/今日小猪`
- `/今天是什麼小豬`
- `/今天是什么小猪`
- `/抽小豬`
- `/抽小猪`
- `/我的小豬`
- `/我的小猪`
- `/rollpig`

行為：

- 第一次使用會為自己抽取當日小豬。
- 同一使用者同一天再次使用只會查看既有結果，不會重抽。
- 每次正常抽取會更新永久圖鑑、抽取次數與相關統計。
- 每日邊界由 `timezone` 配置決定，不一定等於伺服器所在地的午夜。
- 如果昨天被「吃群友」成功吃掉，今天第一次抽取可能依 `eaten_next_day_failure_percent` 失敗；一旦失敗，當天會維持無法抽取狀態，隔天再恢復。

### `/今日小豬 @某人`

需要 `at_view_pig=true`。

這是**只讀查看**：

- 對方今天已抽取：顯示對方既有結果。
- 對方今天未抽取：只會提示尚未抽取，不會替對方生成結果。
- 一次只允許查看一人。
- 此功能不能用來替別人解鎖圖鑑，也不能繞過對方的抽取限制。

## 圖鑑與歷史

### `/我的豬圈 [頁碼]`

別名包括 `/我的猪圈`、`/小豬圖鑑`、`/小猪图鉴`、`/豬圈`、`/猪圈`。

- 每頁 12 隻。
- 顯示永久解鎖情況。
- 重複抽中同一小豬會累計抽取次數並影響 `EX Lv.`。
- 例：`/我的豬圈 2`。

### `/昨日小豬`

別名包括 `/昨日小猪`、`/昨天小豬`、`/昨天小猪`。

顯示昨天真實保存的抽取結果。如果昨天沒有紀錄則直接提示無紀錄。

### `/明日小豬`

別名包括 `/明日小猪`、`/明天小豬`、`/明天小猪`。

- 根據使用者與明日日期生成固定預測。
- 顯示 1–5 星「明日豬運」。
- 不會提前寫入明日抽取，也不會提前解鎖圖鑑。

### `/本週小豬`

別名包括 `/本周小猪`、`/本週小猪`、`/本周豬報`、`/本週豬報`。

生成本週七日摘要；未抽取日期會標記為未抽取，未到日期會標記為等待未來。若某天的小豬後續被吃掉，週報仍能保留對應狀態資訊。

### `/隨機小豬 [1-9]`

別名包括 `/随机小猪`、`/隨機小猪`、`/随机猪`、`/隨機豬`。

- 預設展示 1 隻。
- 可指定 1–9 隻。
- 從目前本地有效圖鑑隨機抽樣。
- 不改變今日結果，也不會永久解鎖展示到的小豬。

### `/找豬 關鍵詞`

別名包括 `/找猪`、`/搜豬`、`/搜猪`。

搜尋欄位：

- `id`
- `name`
- `description`
- `analysis`

最多在結果卡上展示前 9 隻，並顯示總匹配數。

## 今日烤豬

### `/今日烤豬`

別名：`/今日烤猪`、`/烤豬`、`/烤猪`。

需要 `enable_roast=true`。

- 必須先抽取今日小豬。
- 不會改變今日抽取結果。
- 生成趣味料理卡。
- 「人類」、「吃掉了」以及已屬熟食形態的小豬不能再次參與一般烤豬流程。
- 若 `enable_ai_roast_copy=true`，插件會嘗試使用當前會話模型生成料理文案；失敗或超時時回退本地模板。

AI 文案有額外節流：同一隻小豬同一天最多實際發起一次模型生成嘗試；成功文案會在近七個自然日的窗口內供後續隨機復用。

## 烤群友

### `/烤群友 @某人`

需要：

- 群聊環境。
- `enable_roast=true`。
- `enable_group_roast=true`。
- 目標今天已抽取且仍是可料理的小豬。
- 不能對自己使用；想烤自己請用 `/今日烤豬`。

可以直接 @ 目標，也可以回覆對方訊息後使用。

普通烤群友的隨機結果為：

- 60%：成功，目標上桌。
- 30%：目標逃脫。
- 10%：烤架反噬，改為發起者自己的今日小豬上桌；若發起者當前不可料理則幸免。

普通烤群友按「發起者 + 群組」計算冷卻，預設 8 小時，可由 `group_roast_cooldown_hours` 調整。

### `/隨機烤群友`

別名：`/随机烤群友`。

從今天在當前群聊抽過小豬、且目前符合烤豬資格的其他成員中隨機選一位，再套用正常的烤群友流程。

## 被烤保護

當 `enable_roast_protection=true` 時，插件會按「同一群聊」統計前一天某人實際被烤到的次數。

- 達到 `roast_protection_threshold` 後，該成員次日會受到普通烤群友保護。
- 逃脫不計入被烤次數。
- 反噬計入真正被反噬上桌的發起者。
- 吃群友在選擇目標時也會尊重此保護。
- 後門強制模式可以繞過保護，但仍不繞過基本資格限制，例如人類、已被吃或沒有今日小豬。

## 吃群友

### `/吃群友 @某人`

需要 `enable_group_eat=true`，且只能在群聊中對有效目標使用。

- 成功率由 `eat_success_percent` 控制，預設 15%。
- 成功：目標今日狀態變成「吃掉了」。
- 失敗：發起者自己變成「吃掉了」。
- 被吃者次日第一次抽豬會依 `eaten_next_day_failure_percent` 進行懲罰判定。
- 「人類」不能被吃，也不能發動吃群友。
- 已經是「吃掉了」的目標不能再次被吃。
- 部分熟食形態可以作為吃群友目標。
- 被烤保護中的成員不能被普通吃群友選中。

### `/隨機吃群友`

別名：`/随机吃群友`。

從本群今日已抽取、可被吃且未受保護的其他成員中隨機選一位，再執行正常吃群友流程。

## 豬圈日報

### `/豬圈日報`

別名：`/猪圈日报`、`/今日豬圈日報`、`/今日猪圈日报`。

只可在群聊中使用，輸出：

- 本群今日抽豬人數。
- 本群今日被吃人數。
- 若存在被吃成員，隨機點名一位獲得「可憐被吃」稱號。

## 烤群友後門口令

以下命令入口共用同一後門流程：

- `/打點後廚` / `/打点后厨`
- `/偷換烤架` / `/偷换烤架`
- `/賄賂主廚` / `/贿赂主厨`
- `/加急生火`
- `/強行點火` / `/强行点火`

使用方式仍需指定目標，例如：

```text
/打點後廚 @某人
```

規則：

- 一般後門每位發起者每天只能使用一次。
- 後門會繞過普通烤群友的冷卻、被烤保護與 60/30/10 隨機結果，直接按成功流程處理。
- 後門**不會**繞過基本資格限制：必須在群聊、目標必須存在今日小豬、不能烤自己、人類／已吃掉／不可料理形態仍會被拒絕。
- `/強行點火` 僅 AstrBot 超級管理員可使用。

## 功能開關與指令關係

| 配置 | 影響 |
| --- | --- |
| `at_view_pig` | `/今日小豬 @某人` |
| `enable_roast` | 所有烤豬相關功能的總開關 |
| `enable_group_roast` | 烤群友、隨機烤群友、後門口令 |
| `enable_group_eat` | 吃群友、隨機吃群友 |
| `enable_roast_protection` | 普通烤群友與吃群友的次日保護 |
| `enable_ai_roast_copy` | AI 料理文案生成 |

完整配置值見 [`CONFIGURATION.md`](CONFIGURATION.md)。

## 常見誤解

### @ 別人會替對方抽豬嗎？

不會。`at_view_pig` 僅提供只讀查看，對方沒有結果時不會產生結果。

### `/隨機小豬` 會解鎖圖鑑嗎？

不會。它只是展示工具。

### `/明日小豬` 會鎖定明天真正抽到的結果嗎？

不會。它是固定預測，但不會提前寫入明日抽取或提前解鎖。

### 被吃後今天就永遠不能玩了嗎？

「吃掉了」狀態只屬於當天；真正的跨日影響是次日第一次抽豬可能失敗。具體概率由配置控制。
