# 小豬資源管理手冊

本文對應 v3.4.0，面向需要維護本地圖鑑、AstrBot／私人豬源或 PigHub 投稿的插件管理員。

## 1. 資源分層模型

最終圖鑑不是由單一 `pig.json` 直接覆蓋，而是按層合併：

1. **基礎層**：成功同步的 AstrBot 專用源或私人源；遠端不可用時使用插件內置資源。
2. **本地覆蓋層**：管理面板新增的記錄，以及對基礎記錄的名稱、描述、文案或圖片修改。
3. **刪除屏蔽層**：被管理員刪除的 ID，優先級最高。

| 操作 | 結果 |
| --- | --- |
| 新增一個基礎層不存在的 ID | 顯示為「本地新增」 |
| 編輯一個基礎層已有的 ID | 顯示為「覆蓋基礎源」 |
| 上傳自訂圖片 | 圖片優先於私人源及內置圖片 |
| 刪除小豬 | 移除本地覆蓋及自訂圖片，加入屏蔽清單 |
| 取消屏蔽 | 移除 tombstone；基礎層仍有同 ID 時立即恢復 |

若取消屏蔽時基礎層沒有同 ID，操作仍會成功，但需要重新新增記錄才會重新顯示。

## 2. 管理面板工作流

### 查看本地改動

打開「插件頁面 → 今日小豬 → 本地資源」：

- 「本地新增與覆蓋」列出所有本地 override。
- 每張卡片會標示是本地新增還是覆蓋基礎源。
- 是否使用本地圖片會獨立顯示。
- 點擊「編輯」可進入完整編輯流程。

### 下載原圖重修

1. 在圖鑑或本地資源頁打開一隻小豬的編輯視窗。
2. 點擊「下載原圖重修」。
3. 在本地完成裁切、繪製或修復。
4. 回到編輯視窗，選擇「本地上傳」替換圖片。
5. 保存後圖片會統一為 `512×512 PNG`。

下載的是目前真正生效的圖片：本地圖片優先，其次 AstrBot／私人源，最後才是內置資源。

### 取消屏蔽

1. 打開「本地資源 → 刪除屏蔽」。
2. 確認 ID、名稱與基礎層狀態。
3. 點擊「取消屏蔽」並再次確認。
4. 面板會同時刷新總覽、圖鑑、資源層與同步狀態。

## 3. AstrBot 專用源與私人 manifest

插件預設連接本專案維護的 AstrBot v1 專用源：

```text
https://curryudon.top/astrbot-rollpig/v1/manifest.json
```

你也可以把 `resource_manifest_url` 改成有權使用的 HTTPS 私人 manifest。

最小示例：

```json
{
  "resource_version": "2026.08.14-1",
  "pig_json": {
    "path": "pig.json",
    "size": 1234,
    "sha256": "64位小寫十六進制SHA256"
  },
  "images": [
    {
      "filename": "pig.png",
      "path": "images/pig.png",
      "size": 5678,
      "sha256": "64位小寫十六進制SHA256"
    }
  ]
}
```

對應 `pig.json`：

```json
[
  {
    "id": "pig",
    "name": "小豬",
    "description": "普通但可靠",
    "analysis": "今天適合把簡單的事情做好。"
  }
]
```

### 必要條件

- manifest 必須是 HTTPS URL。
- `resource_version` 不能為空；內容有變更時應同步更新。
- `pig_json` 與每張圖片都必須聲明 `size` 和 SHA-256。
- `pig.json` 中每個 ID 都必須存在同名圖片。
- ID 只允許小寫字母、數字、`-`、`_`，長度 1–64。
- 圖片副檔名只允許 PNG、JPG、JPEG、WEBP、GIF。
- manifest 最多 500 張圖片，整包聲明大小不得超過 128 MiB。
- 單檔上限由 `resource_max_file_size_mb` 控制。

### 部署建議

- 對 manifest 與資源使用穩定 HTTPS 靜態託管。
- 保留舊版本，方便發現內容問題時回退。
- 先在測試實例手動同步，再打開自動同步。
- 不要把需要 Cookie、登入或特定客戶端 User-Agent 的地址當作公共 manifest。

## 4. 為什麼舊雲端來源會失敗

舊版預填的 `https://pig.felislab.cc/resources/rollpig/manifest.json` 屬於 `nonebot-plugin-rollpig-plus` 的受限官方源。服務端會對本 AstrBot 插件回傳 HTTP 403，並拒絕未授權客戶端。

這不是 manifest 解析、圖片格式或 SQLite 問題。v3.4.0 的處理方式：

- 新安裝預設啟用 AstrBot v1 專用源。
- 舊 nonebot URL 會精確遷移到新來源；自訂私人 URL 不會被覆蓋。
- 新來源要求 `X-RollPig-Client`、`X-RollPig-Protocol` 與 AstrBot 版本化 User-Agent。
- 普通瀏覽器、錯誤客戶端和 nonebot 請求會回傳 HTTP 403，AstrBot v1 客戶端正常取得資源。
- 遠端失敗時仍保留既有快取，沒有快取時回退內置資源與全部本地改動。

協議標頭可被開源客戶端模仿，作用是阻擋誤用與不相容客戶端，不等同密碼學認證。封閉私人源請額外加入每實例 Token 或 mTLS。來源的建構、部署與回退見 [`RESOURCE-SOURCE-MAINTENANCE.md`](RESOURCE-SOURCE-MAINTENANCE.md)。

## 5. PigHub 公共審核投稿

[PigHub](https://pighub.top/) 是圖片分享與人工審核平台，不是完整的 RollPig manifest 服務。

### 投稿內容

會提交：

- 小豬名稱。
- 目前生效的圖片。

不會提交：

- 小豬描述與完整文案。
- 使用者、群組或聊天資料。
- SQLite、JSON 備份或插件配置。

### 投稿流程

1. 只能從「本地新增與覆蓋」清單發起。
2. 管理員必須在瀏覽器確認公開提交。
3. 插件檢查圖片格式與 10 MB 上限。
4. 依 PigHub 公開網頁流程上傳圖片。
5. 將圖片 URL 與名稱加入 PigHub 待審核隊列。
6. 成功只代表已進入隊列，不代表審核通過。

插件不會自動重試具有副作用的投稿請求，也不會輪詢審核狀態，避免重複提交。

## 6. 安全邊界

- 管理寫操作要求同源請求及 CSRF token。
- PigHub 投稿端點固定，管理員不能從面板指定任意上傳 API。
- 遠端回應有大小限制，圖片 URL 必須是無帳密的 HTTPS 地址。
- 私人源下載會拒絕私網、回環、保留及不安全目的地。
- 全包校驗完成前不替換 active 資源。
- 同步失敗時保留舊快取；沒有快取時回退內置層。

## 7. 常見問題

### 面板顯示「來源不可用」

舊 nonebot 地址在 v3.4.0 會自動遷移。若自訂源仍顯示不可用，檢查 HTTPS、協議欄位、大小、SHA-256 與伺服器回應。

### 取消屏蔽後仍看不到小豬

代表目前基礎層沒有同 ID，且刪除時本地專屬記錄／圖片已被移除。請重新新增。

### 投稿成功但 PigHub 沒有立即顯示

公開頁明確採人工審核；成功回應只表示加入待審核隊列。

### 私人源更新後本地編輯消失了嗎

不會。私人源只替換基礎層，本地 override 與 tombstone 仍在更高優先級。

### 同步失敗會不會清空圖鑑

不會。下載、JSON、大小、SHA-256、圖片與完整性檢查全部通過後才原子切換。
