# 預約烤豬

預約烤豬把「目標今天還沒抽豬」從一次失敗提示改成同群當日的異步埋伏玩法。它只作用於明確指定目標的普通 `/烤群友 @某人`；隨機烤群友和後門強制模式保持原行為。

## 建立與添柴

當 `enable_roast_reservation=true` 且目標今天尚未抽豬時：

1. 第一位使用 `/烤群友 @目標` 的有效玩家成為固定主廚。
2. 主廚必須先抽到自己今天可料理的小豬，並支付一次普通群烤所需的 Roast Charge。
3. 同一天、同一群、同一目標只存在一張待結算預約。
4. 主廚建立預約時已經算第 1 位參與者，**不能再替自己的預約重複添柴**。
5. 後續其他群友加入預約有兩種入口：
   - `/添柴 @目標`：最明確的預約添柴入口；
   - 再次 `/烤群友 @同一目標`：保留相容，不再建立第二張預約，也不再扣一次 Charge。
6. 如果目前**沒有進行中的烤箱補貨**，且本群今天剛好只有一張待結算預約，裸 `/添柴` 也會直接加入那張預約。
7. 同一參與者重複添柴不重複計數。
8. 參與人數包含主廚，預設上限 12，可由 `roast_reservation_max_participants` 在 2–20 之間調整。

> [!TIP]
> `/添柴` 同時服務兩個後廚場景，但插件會自己判斷上下文：
>
> - **補貨輪次正在進行**：裸 `/添柴` 優先支持烤箱補貨；
> - **想明確支持某張預約**：使用 `/添柴 @目標`；
> - **沒有補貨、只有一張待結算預約**：裸 `/添柴` 直接蹲那口鍋；
> - **沒有補貨、但有多張預約**：插件會要求你 `@目標`，不替你猜要往哪口鍋塞柴。
>
> 舊 `/添煤`、`/加煤`、`/烤箱添煤`、`/烤箱添柴` 只作補貨相容入口，不在玩家幫助中主推。

建立預約仍尊重昨日過度被烤保護。後門口令不建立預約，也不會把尚未抽豬的目標強行變成可烤狀態。

## 何時觸發

預約以「自然日 + 群組 + 目標」隔離。目標本人在**同一群**正常使用 `/今日小豬` 並顯示自己的今日結果時，待結算預約才會觸發。

這意味著：

- 目標在其他群抽過豬，不會把本群埋伏結果投遞到錯誤群；
- 只讀 `/今日小豬 @某人` 不會替被查看者觸發預約；
- 目標之後回到預約群再次查看自己的今日小豬，仍可觸發當日尚未結算的埋伏；
- 預約不跨自然日繼承，舊狀態會按日期裁剪。

建立／添柴與抽豬後觸發結算共用同一把預約鎖。取得鎖後會再次確認目標的今日狀態；已經 `resolved` 的同日預約也視為終態，不允許競態請求重新打開。這避免「目標剛抽豬」與「另一位玩家剛好添柴」同時發生時留下第二張永遠不會正常觸發的預約。

如果 `/添柴` 在等待鎖期間目標剛好完成抽豬，插件會明確回覆「原預約正在結算」，而不是再把參與者寫進已經掀鍋的預約，也不會把命令留給聊天模型接管。

## 結算

建立預約時已經支付普通群烤所需的 Charge，因此觸發時**不會再扣第二次**。結果沿用普通烤群友：

- 60%：成功，目標今日小豬上桌；
- 30%：目標逃脫；
- 10%：反噬固定主廚；如果主廚當時沒有可料理的小豬則幸免。

添柴人數目前是社交展示和事件資料，不直接增加成功率，避免多人堆到 100% 成功而破壞原本 60/30/10 的戲劇性。

## 一次性與投遞安全

預約會在任何結算訊息發送前先從 `pending` 原子標記為 `resolved`，並固定本次 outcome。這是刻意的「至多一次」語義：如果某個訊息適配器在已接受消息後回報超時，插件不會因自動重試而再次烤一次。

同日、同群、同目標一旦已有 `resolved` 記錄，`create_or_join_reservation()` 不會把它重新建立成 `pending`。若之後玩家再次 `/烤群友 @目標`，會回到普通烤群友流程，而不是重啟舊預約。

狀態保存在插件資料目錄的 `roast_reservations.json`，只保存短期玩法所需的日期、群、主廚、目標、參與者和結算狀態；小豬收藏、Charge 與被烤次數仍由現有 SQLite／JSON 權威資料管理。

## Gameplay Event

預約流程寫入共用 Gameplay Event v1：

- `roast_reservation_created`
- `roast_reservation_joined`
- `roast_reservation_triggered`
- 最終仍寫既有 `roast_success` / `roast_escape` / `roast_backlash`

因此現有豬圈日報的燒烤、逃脫、反噬和稱號統計能自然納入預約結算，不需要另外維護一套日報統計。

## 配置

| 配置 | 預設 | 說明 |
| --- | --- | --- |
| `enable_roast_reservation` | `true` | 允許明確指定未抽豬目標時建立預約／添柴 |
| `roast_reservation_max_participants` | `12` | 每張預約最多參與人數，包含主廚，範圍 2–20 |
| `group_roast_max_charges` | `2` | 主廚建立新預約時支付一格普通群烤 Charge；後續添柴不消耗 |
| `enable_roast_protection` | `true` | 預約建立同樣尊重昨日過度被烤保護 |
