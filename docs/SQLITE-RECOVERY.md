# SQLite 恢復保護

本頁描述維護第一批的未發佈變更；不是 v3.12.1 已有的行為。

## 何時停止載入

正常運行以 SQLite 為核心資料權威，兼容 JSON 不會持續雙寫。因此，既有資料庫無法開啟或驗證失敗時，插件現在停止載入，不用舊或空 JSON 繼續抽豬。資料庫消失但 storage_state.json 仍標示 SQL 權威、狀態文件無法核驗、或只剩 WAL／SHM，亦不能當成新安裝。

本批沒有新增只讀管理頁或自動恢復精靈。插件未載入時，其工作台也不可用；請在 AstrBot 載入日誌查看 `SQLite 需要恢复` 及原始原因。這比以錯誤資料顯示正常運行更保守。

## 管理員處理

1. 停止插件；不確定是否仍有其他程序寫入時，停止 AstrBot。
2. 備份整個 `data/plugin_data/astrbot_plugin_rollpig_plus` 資料目錄，而不是只複製 rollpig.db。保留 WAL／SHM、preflight 副本、storage_state.json、舊 JSON、本地圖片與 EX；不要先刪除、改名或手工清空資料庫。
3. 在備份副本上排查磁碟空間、檔案權限、鎖定及資料庫完整性。不能僅因一次鎖定或 I/O 錯誤就判定資料庫不可修復。
4. 核验可恢复数据库或备份的时间、来源及收藏事实，再在停机状态恢复。JSON 匯出包不是完整資料目錄備份；其時間可能早於最新 SQL 進度，必須說明可能的進度損失。
5. 使用 auto／sqlite 模式重新載入並驗證收藏。只有成功載入 SQL 後，才能用既有工作台的驗證、匯出或對賬回滾操作。

不要單純改成 `storage_backend=json` 繞過保護。JSON 模式只接受原生 JSON 安裝，或經既有 SQL → JSON 匯出、對賬及停用資料庫流程完成的回滾安裝。恢復健康 SQL 後，可先用 auto 載入，再從工作台明確回滾。

## 仍保留的相容行為

全新安裝會建立 SQLite。可讀的舊 JSON 初次遷移在正式数据库提交前失敗時，仍使用原 JSON；來源 JSON 本身不可讀則停止，不把損壞來源覆寫為空預設值。健康 SQL 的可推導狀態修復、已驗證的匯出／回滾及舊 v2 類別公開 API 不變。

本批不改 SQLite schema、插件身份、玩家資料路徑、EX 算法或 Resource Protocol v1。公共鏡像仍停用；此資料恢復保護與素材鏡像授權是不同責任。
