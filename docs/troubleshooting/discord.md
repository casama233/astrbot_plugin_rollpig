# 在 Discord 輸入 `/` 卻沒有顯示選單

**純文字指令能正常互動，不代表原生選單已經註冊完成。** 選單顯示的前提是 AstrBot 成功將指令清單推送給 Discord，且 Discord 端順利接收。

## 第一步：先確認問題屬於哪一類

| 看到的情況 | 接著做什麼 |
| --- | --- |
| 完全沒有這個機器人的指令 | 管理員檢查下方的註冊開關與同步紀錄 |
| 有其他指令，唯獨沒有小豬 | 確認小豬插件已啟用，再重新連線 Discord 適配器以同步清單 |
| 選單能選，但沒有回覆 | 改查插件回覆、權限與網路錯誤；這是另一段流程 |
| 只有某個人或頻道看不到 | 檢查 Discord 的「使用應用程式指令」權限與伺服器的整合設定 |

小豬插件在原生選單中統一註冊簡體主指令，例如 `今日小猪`、`我的猪圈`。至於繁體或其他別名指令，可以直接在對話框發送使用，但不會一一列在選單裡。

## 管理員排查：先檢查註冊日誌

1. 請先前往 AstrBot 的 Discord 平台設定，確認 `discord_command_register` 處於開啟狀態。
2. 接著查看 Discord 連線後的運行日誌。出現 `Ready to sync` 僅代表指令清單已打包就緒；必須看到 `Command synchronization completed` 才算是真正同步成功。
3. 若日誌有報錯，請參照下方說明排解。修正完成後，只需重新連接 Discord 適配器即可驗證結果。

| 日誌訊息 | 原因與處理 |
| --- | --- |
| `50035`，`Application command names must be unique` | 同名指令重複送出，Discord 拒絕整批。應修正 AstrBot 適配器的註冊去重，保留處理順序中優先的同名項；不用刪除小豬資料或改掉玩家指令。 |
| `30034` | Discord 的每日建立指令配額已用完。停止反覆重註冊，等配額恢復。 |
| 權限或授權錯誤 | 檢查機器人的安裝範圍是否包含應用程式指令，以及所在伺服器的整合權限。 |
| 網路或逾時錯誤 | 檢查 Discord 代理與連線；修好連線後再同步。 |

!!! note "文字指令可先使用"
    在原生選單修復之前，玩家可以直接發送 `/今日小豬` 來遊玩。發送時是否需要 @ 機器人，則視 AstrBot 的喚醒規則設定而定。

原生斜線選單由 AstrBot 的 Discord 適配器負責管理，小豬插件只提供指令定義與回覆邏輯；反覆重裝小豬插件，並無法解決適配器送出重名清單的問題。
