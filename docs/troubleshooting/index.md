# 🧯 常見故障

先分清楚：**是玩法規則正在阻擋你，還是真的出錯。**

## `/今日小豬` 今天抽不到

先看兩件事：

1. **昨天是否被吃掉。** 預設情況下，被吃後第二天第一次抽豬有 20% 機率強制抽到一隻已解鎖的重複豬；抽取仍會正常完成，不會鎖到自然日結束。
2. **時區是否符合預期。** 每日邊界由 `timezone` 決定，不一定等於你本地的午夜。

如果兩者都不是，再看後台日誌是否有 storage、圖片或資源錯誤。

## `/今日小豬 @某人` 沒有查看對方

這個功能需要管理員先開啟：

```text
at_view_pig = true
```

開啟後，`/今日小豬 @某人` 只會查看對方已經存在的今日結果；**不會替對方抽豬、解鎖收藏或觸發預約**。

如果沒有開啟 `at_view_pig`，請先讓管理員確認配置。

## `/烤群友 @某人` 不能用

按順序檢查：

- 是否在群聊；
- `enable_roast` 和 `enable_group_roast` 是否開啟；
- 你自己今天是否有可料理的小豬；
- 目標是否是自己；
- 目標是否為人類、已被吃掉或其他不可料理狀態；
- 目標是否有次日保護；
- 你的 Roast Charge 是否已用完。

如果目標今天還沒抽豬，而且開啟了預約功能，明確 `/烤群友 @某人` 會建立預約，不會立刻結算。

[完整群烤規則 →](../gameplay/roast-outcomes.md)

## 明明烤 A，為什麼料理卡是我？

普通群烤可能出現反噬。預設結果是：

- 60% 成功
- 30% 逃脫
- 10% 反噬

反噬時，如果主廚自己的今日小豬可料理，真正被烤的是主廚。

## `/烤箱補貨` 說我沒資格

發起者和支持者都必須是**今天在這個群形成過 RollPig 活躍記錄的玩家**。

另外也可能是：

- 今天本群已達補貨成功上限；
- 已有一輪正在進行；
- 管理員關閉了 `enable_oven_refill`。

自己已經滿 Charge 仍可以幫忙支持；只是成功後不會突破最大容量。

## `/添柴` 沒有加人頭

`/添柴` 有兩種用途：補貨和預約。常見失敗原因包括：

- 你今天沒有在本群參與 RollPig；
- 你自己今天沒有可料理的小豬；
- 你已經支持過同一輪／同一張預約；
- 你是預約主廚或預約目標本人；
- 沒有有效的補貨輪次或待結算預約；
- 同時有多張預約，但你沒有指定 `@目標`；
- 預約已滿員或剛好開始結算。

補貨進行中時，裸 `/添柴` 優先補貨；想明確加入預約就用 `/添柴 @目標`。

`/添煤`、`/加煤` 等舊寫法只保留作補貨相容入口，玩家建議直接使用 `/添柴`。

[完整 Charge 與添柴規則 →](../gameplay/roast-charge.md)

## 日報為什麼不自動發？

自動日報需要同時滿足：

1. 全局 `daily_report_auto_send = true`；
2. 這個群已由 AstrBot 管理員明確開啟自動日報。

先在群裡輸入：

<span class="pig-command">/豬圈日報狀態</span>

如果 `daily_report_skip_empty_groups=true`，當天沒有抽豬活動的群也會被跳過。

手動 `/豬圈日報` 永遠只讀，不會觸發可選的「今日祭品」。

## 資源同步出現 403

如果仍使用舊地址：

```text
https://pig.felislab.cc/resources/rollpig/manifest.json
```

請改用目前 AstrBot 專用來源或讓新版自動遷移。官方預設為：

```text
https://curryudon.top/astrbot-rollpig/v1/manifest.json
```

如果是自訂私人源出現 403，檢查自己的認證、Header 或反向代理設定。

## 同步失敗會不會清空圖鑑？

正常不會。遠端資源會先完整驗證，成功後才切換；失敗時會繼續使用舊快取，沒有快取則回退內置資源。

所以不要因一次同步失敗就先刪 `cloud_resources/` 或資料庫。

## 投稿成功，但公共源找不到

投稿成功只代表**進入人工審核隊列**，不是立即發佈。維護者批准並生成新資源版本後，其他實例還要等下一次同步。

[創作者與投稿流程 →](../creators/index.md)

## 更新後版本／管理頁看起來沒變

插件更新完成後不會自動重啟 AstrBot。先確認更新成功，再重啟或重新載入插件。

如果是舊版 overlay 升級留下的管理頁殘留，v3.8.1 之後會在啟動時自動清理已知的舊 Plugin Page。

## SQLite 看起來有問題，可以直接刪 `rollpig.db` 嗎？

不建議。先：

1. 停止持續寫入；
2. 備份完整插件資料目錄；
3. 查看實際 storage 錯誤；
4. 再決定恢復、回退或重新遷移。

[運維、備份與恢復 →](../OPERATIONS.md)

## 回報 bug 最好帶什麼？

請至少附上：插件版本、AstrBot 版本、適配器、問題指令、群聊／私聊、錯誤時間附近的日誌，以及相關配置值。

**不要貼 Token、密鑰或其他私密憑證。**
