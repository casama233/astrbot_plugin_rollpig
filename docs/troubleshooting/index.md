# 🧯 常見故障

先分清：**是玩法规则在拦路，还是程序真罢工了。**

## `/今日小豬` 今天抽不到

先排查两件事：

1. **昨天是否被吃掉。** 默认情况下，被吃后次日首抽有 20% 概率必出已解锁的重复猪；抽取仍正常完成，不会锁到自然日结束。
2. **时区是否对得上。** 每日重置时间由 `timezone` 决定，不一定跟着你本地的午夜走。

如果都不是，再去后台日志翻翻有没有 storage、图片或资源报错。

## `/今日小豬 @某人` 沒有查看對方

这功能得先让管理员开闸：

```text
at_view_pig = true
```

开启后，`/今日小豬 @某人` 只会偷看对方已有的今日结果；**不会替对方抽猪、解锁图鉴或触发预约**。

要是没开 `at_view_pig`，先喊管理员检查配置。

## `/烤群友 @某人` 不能用

按顺序挨个查：

- 是不是在群聊里；
- `enable_roast` 和 `enable_group_roast` 是否已开启；
- 你自己今天有没有可料理的小猪；
- 目标是不是你自己；
- 目标是不是人类、已被吃掉或处于其他不可料理状态；
- 目标是否带着次日保护；
- 你的 Roast Charge 是不是已经用光了。

如果目标今天还没抽猪且开启了预约功能，明确 `/烤群友 @某人` 会挂上预约，不会当场开烤结算。

[完整群烤規則 →](../gameplay/roast-outcomes.md)

## 明明烤 A，為什麼料理卡是我？

普通群烤可能会翻车反噬，默认后果是：

- 70% 成功
- 20% 逃脫
- 10% 反噬

一旦反噬，只要主厨自己的今日小猪可料理，被架上烤架的就是主厨本人。

## `/烤箱補貨` 說我沒資格

发起者和支持者都得是**今天在本群留下过 RollPig 活跃记录的玩家**。

也可能是这几种情况：

- 今天本群补货成功次数已到上限；
- 已经有一轮正在进行了；
- 管理员关掉了 `enable_oven_refill`。

自己已经满 Charge 仍可以帮忙支持；只是成功后不会突破最大容量。

## `/添柴` 沒有加人頭

`/添柴` 有两种用途：补货和预约。常见失败原因包括：

- 你今天没有在本群参与 RollPig；
- 你自己今天没有可料理的小猪；
- 你已经支持过同一轮／同一张预约；
- 你是预约主厨或预约目标本人；
- 没有有效的补货轮次或待结算预约；
- 同时有多张预约，但你没有指定 `@目標`；
- 预约已满员或刚好开始结算。

补货进行中时，裸发 `/添柴` 优先补货；想明确加入预约就用 `/添柴 @目標`。

`/添煤`、`/加煤` 等旧写法只保留作补货兼容入口，建议直接使用 `/添柴`。

[完整 Charge 與添柴規則 →](../gameplay/roast-charge.md)

## 日報為什麼不自動發？

自动日报需要同时满足：

1. 全局 `daily_report_auto_send = true`；
2. 这个群已由 AstrBot 管理员明确开启自动日报。

先在群里输入：

<span class="pig-command">/豬圈日報狀態</span>

如果 `daily_report_skip_empty_groups=true`，当天没有抽猪活动的群也会被跳过。

手动 `/豬圈日報` 永远只读，不会触发可选的“今日祭品”。

## 資源同步出現 403

如果仍使用旧地址：

```text
https://pig.felislab.cc/resources/rollpig/manifest.json
```

请改用当前 AstrBot 专用来源或让新版自动迁移。官方默认为：

```text
https://curryudon.top/astrbot-rollpig/v1/manifest.json
```

如果是自建私人源出现 403，请检查自己的认证、Header 或反向代理设置。

## 同步失敗會不會清空圖鑑？

正常不会。远端资源会先完整验证，成功后才切换；失败时沿用旧缓存，无缓存则回退内置资源。

所以不要因为一次同步失败就先删 `cloud_resources/` 或数据库。

## 投稿成功，但公共源找不到

投稿成功只代表**进入人工审核队列**，并非立即发布。审核通过并生成新版本后，其他实例还要等下次同步。

[創作者與投稿流程 →](../creators/index.md)

## 更新後版本／管理頁看起來沒變

插件更新完成后不会自动重启 AstrBot。先确认更新成功，再手动重启或重载插件。

如果是旧版 overlay 升级留下的管理页残留，v3.8.1 之后会在启动时自动清理已知的旧 Plugin Page。

## SQLite 看起來有問題，可以直接刪 `rollpig.db` 嗎？

不建议。先：

1. 停止持续写入；
2. 备份完整插件数据目录；
3. 查看实际 storage 错误；
4. 再决定恢复、回退或重新迁移。

[運維、備份與恢復 →](../OPERATIONS.md)

## 回報 bug 最好帶什麼？

请至少附上：插件版本、AstrBot 版本、适配器、问题指令、群聊／私聊、报错前后的日志，以及相关配置值。

**不要贴 Token、密钥或其他私密凭证。**

## Discord 輸入 `/` 沒有選單

先看 [Discord 原生指令排錯](discord.md)。文字指令和原生選單是兩條不同路徑；管理員要確認同步成功，而不是反覆重裝插件。
