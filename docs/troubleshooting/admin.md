# ⚙️ 管理面板定向排障指南

這份指南不是要讓你像看小說一樣從頭讀到尾。

它的存在只有一個目的：**插件哪裡跳出報錯，就把你直接精準送到對應的解法。**

如果你只是想根據外在症狀慢慢排查，請返回 [常見故障總覽](index.md)。

## ☁️ 豬源同步異常 {: #resource-sync }

當管理面板跳出「同步失敗」「來源不可用」「403」或「校驗失敗」時，請先按住性子，千萬別急著刪除 `cloud_resources/`，也別動 `rollpig.db`。

請依序檢查以下步驟：

1. **核對資源來源。** 官方預設來源應為 `https://curryudon.top/astrbot-rollpig/v1/manifest.json`；若配置仍指向舊版 nonebot 受限源，AstrBot 客戶端收到 403 屬於正常預期現象。
2. **檢視面板診斷資訊。** 務必記下具體的 HTTP 狀態碼、manifest URL、校驗錯誤詳情或逾時（timeout）摘要。
3. **確認私人源規範。** 自訂 manifest 若遭遇 401/403，請優先排查自身的權限認證、反向代理設定與請求標頭（header）；先別急著懷疑是 `pig.json` 出了問題。
4. **保留既有快取。** RollPig 會在 staging 區完成全套驗證後才進行原子切換；一旦同步失敗，舊版快取依然會正常運作，只有在完全沒有快取時才會退回使用內置資源。
5. **重新手動觸發同步。** 若錯誤依舊存在，請完整保存同步摘要與該時段的後台日誌，再進行問題回報。

!!! info "一次紅字通常不等於整個豬圈沒了"
    所有遠端資源包都必須通過檔案大小、SHA-256 雜湊、JSON 格式、圖片完整性等層層校驗，才會正式切換上線。同步失敗時的標準容錯策略就是**保留上一份可用資源**。

想了解更完整的資源分層、私人源架設與本地覆寫（override）規則，請移步參閱 [資源管理](../RESOURCE-MANAGEMENT.md)。

## 🧠 深度分析 / 管理頁載入異常 {: #admin-ui }

看到「深度分析未載入」並不等於整個核心插件已經掛掉。

管理頁的數據總覽、豬豬圖鑑與基礎管理操作屬於核心頁面；而深度分析模組的資源則是透過 AstrBot Plugin Page 的認證橋接按需載入的。遇到報錯時請這樣處理：

1. **先讀懂報錯提示本身。** 像是 Bridge 不存在、6 秒內未就緒、資產版本不符或 SHA-256 校驗失敗等具體訊息，遠比無腦重新整理十次頁面更有參考價值。
2. **確認 AstrBot Plugin Page 運作正常。** 假如整個管理頁連後端 API 都無法呼叫，那病灶就不僅僅侷限在 Analytics 模組了。
3. **重新整理管理頁後再試一次。** 藉此排除舊版 SPA 狀態卡死或瀏覽器快取殘留的干擾。
4. **若仍舊失敗，請攜帶日誌回報。** 回報時請附上插件版本、AstrBot 版本、使用的瀏覽器型號、完整錯誤提示，以及後台同一時間點的 traceback 紀錄。

!!! success "核心管理操作不需要等深度分析"
    即便 Analytics 分析資產載入失敗，豬豬圖鑑與常規管理功能也絕不會因此被連帶鎖死——這是我們刻意設計的故障隔離機制。

若遇到的狀況涉及資料庫損毀、資料備份或跨版本遷移，請別在這一節盲目猜測，直接前往 [運維、備份與遷移](../OPERATIONS.md) 尋找解答。
