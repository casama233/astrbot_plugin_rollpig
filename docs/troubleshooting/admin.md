# ⚙️ 管理面板定向排障

這一頁不是要你從頭讀完。

它存在的理由很簡單：**插件哪裡報錯，就把你直接送到哪裡。**

如果你只是想從症狀慢慢排，回到 [常見故障總覽](index.md)。

## ☁️ 豬源同步失敗 {: #resource-sync }

管理面板顯示「同步失敗」「來源不可用」「403」「校驗失敗」時，先不要刪 `cloud_resources/`，也不要碰 `rollpig.db`。

按這個順序看：

1. **確認來源。** 官方預設應是 `https://curryudon.top/astrbot-rollpig/v1/manifest.json`；如果仍指向舊 nonebot 受限源，AstrBot 客戶端收到 403 是預期結果。
2. **看面板診斷。** 記下 HTTP 狀態碼、manifest URL、校驗錯誤或 timeout 摘要。
3. **確認私人源規則。** 自訂 manifest 遇到 401/403 時，檢查自己的認證、反代與 header；不要先懷疑 `pig.json`。
4. **保留舊快取。** RollPig 會在 staging 完整驗證後才原子切換 active；失敗時舊快取仍應繼續工作，沒有快取才回退內置資源。
5. **再手動同步一次。** 如果錯誤持續，保存同步摘要與對應時間點日誌再回報。

!!! info "一次紅字通常不等於整個豬圈沒了"
    遠端包要通過大小、SHA-256、JSON、圖片和完整性校驗才會正式切換。同步失敗的正常策略是**保留上一份可用資源**。

更完整的資源層、私人源與本地 override 規則看 [資源管理](../RESOURCE-MANAGEMENT.md)。

## 🧠 深度分析 / 管理頁載入失敗 {: #admin-ui }

「深度分析未載入」不等於核心插件壞掉。

管理頁的資料總覽、豬豬圖鑑和基本管理功能是核心頁；深度分析資產是透過 AstrBot Plugin Page 的認證橋接按需載入。看到錯誤時：

1. **先看提示本身。** 如果是 Bridge 不存在、6 秒未就緒、資產版本不匹配或 SHA-256 校驗失敗，這些訊息比重新整理十次更有用。
2. **確認 AstrBot Plugin Page 正常。** 如果整個管理頁都無法呼叫後端 API，問題不只在 Analytics 模組。
3. **刷新管理頁後重試一次。** 避免舊 SPA 狀態或瀏覽器快取殘留。
4. **仍然失敗就帶日誌。** 回報插件版本、AstrBot 版本、瀏覽器、錯誤提示，以及後台同時間的 traceback。

!!! success "核心管理操作不需要等深度分析"
    即使 Analytics 資產載入失敗，圖鑑與一般管理操作不應因此被鎖死。這是刻意的故障隔離。

如果問題是資料庫、備份或遷移，不要在這一節硬猜，直接看 [運維、備份與遷移](../OPERATIONS.md)。
